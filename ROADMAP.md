## 1. Executive Summary & Core Architecture

The goal of this project is to build a modern, open-source, cross-platform equation editor and converter that works seamlessly on **Windows, macOS, and Linux**, operating with a **modern Add-in workflow** (like the new MathType Add-in) while maintaining **100% backward & forward compatibility** with both legacy and modern MathType formats in **Microsoft Word** and **WPS Office**.

### Key Capabilities & Workflow
1. **Modern Add-in UX (Familiar MathType Experience):**
   - Dedicated **Math Editor Ribbon Tab** in Microsoft Word and WPS Office.
   - **Select & Edit Workflow:** Select an existing equation in the document ➔ click **Edit Equation** on the Ribbon ➔ opens the equation in the modal/popup editor window (with classic symbol palettes, virtual keyboard, and inline LaTeX shortcuts).
   - **Prompt-on-close (`[X]` button):** *"Do you want to insert/update this equation in the document? [Yes] [No] [Cancel]"*.
   - **LaTeX Toggle in Document:** Select inline LaTeX text (e.g. `$x^2 + y^2$`) in Word/WPS ➔ click **Toggle LaTeX** on the Ribbon to convert it into a formatted equation in-place.
2. **Embedded MTEF Data Inside Vector `.emf` (`EMR_COMMENT` + `AppsMFCC`):**
   - Every vector `.emf` preview generated by [`src/render/emf.rs`](src/render/emf.rs) embeds the **MTEF 5.0 binary stream** (with the standard `AppsMFCC` + `"Design Science, Inc.\0"` signature) inside an `EMR_COMMENT` record (`0x46`), plus an optional MathML comment payload.
   - **Why this matters:** Modern MathType (and our Add-in) can recover and edit the equation directly from the `.emf` image metadata even if the OLE `.bin` container is stripped by Word Online, macOS, or third-party editors.
   - Full bidirectional extraction: [`src/ole.rs`](src/ole.rs) extracts MTEF from OLE `.bin`, legacy `.wmf` (`META_ESCAPE`), and modern `.emf` (`EMR_COMMENT`).
3. **One-Click "Convert Legacy MathType ➔ Modern MathType":**
   - Dedicated button on the Ribbon and in the Desktop Batch Converter to upgrade old documents containing legacy **Microsoft Equation 3.0 (`Equation.3` / MTEF 3.0)**, broken/blurry **`.wmf` equations**, or old MathType OLE objects into two selectable modern targets:
     - **Target A — Modern Add-in Format (Native OMML `<m:oMath>`):** Editable natively in Word 365, Word on Mac/Web, WPS Office, and modern MathType Web Add-in.
     - **Target B — Modern MathType 7 (`Equation.DSMT4` OLE + Vector `.emf` with embedded MTEF 5.0):** Upgrades MTEF v3 ➔ MTEF v5.0, re-renders blurry `.wmf` previews into razor-sharp STIX Two Math vector `.emf` (with embedded `EMR_COMMENT` MTEF data), and wraps them in a clean `Equation.DSMT4` OLE package.
4. **Flat OPC (`pkg:package`) Single-Equation Bridge:**
   - Generates self-contained **Flat OPC XML** strings for single equations (including base64-encoded `oleObject*.bin` and `equation*.emf` parts) so Word (`setSelectedDataAsync` with `CoercionType.Ooxml`) and WPS (`InsertXML`) can insert or replace individual equations in real time without touching or locking the `.docx` file on disk.
5. **Lightweight & Fast Desktop Agent:**
   - Powered by **Rust** and **Tauri v2** (< 20MB installer, ~80–120MB WebView RAM when active, < 150ms warm-popup from System Tray).

## 3. Phased Implementation Roadmap

### Phase 1: Core Engine Enhancements (EMF Data Embedding & Flat OPC)
**Goal:** Upgrade the existing Rust `omml-converter` crate to embed/extract MTEF inside `.emf` files, support single-equation Flat OPC snippets for Add-in insertion, and upgrade legacy MathType equations.

- [x] **Existing Core Pipelines (Already Implemented in Repo):**
  - OMML ⇄ MathML ([`src/omml/`](src/omml/mod.rs)).
  - MathML ⇄ MTEF 5.0 encoder & MTEF 3/5 decoder ([`src/mtef/`](src/mtef/mod.rs)).
  - OLE CFB `.bin` reader/writer & WMF `AppsMFCC` extractor ([`src/ole.rs`](src/ole.rs)).
  - Vector EMF & high-DPI PNG renderer ([`src/render/`](src/render/mod.rs)).
  - Full `.docx` batch conversion OMML ⇄ MathType OLE ([`src/docx/`](src/docx/mod.rs)).
- [x] **Task 1.1: Embed MTEF 5.0 Data into Vector `.emf` (`EMR_COMMENT`)**
  - Update [`render_emf`](src/render/emf.rs) (or add `render_emf_with_mtef`) in [`src/render/emf.rs`](src/render/emf.rs) to write an `EMR_COMMENT` (`0x00000046`) record immediately after `EMR_HEADER`.
  - Format the comment payload using the standard MathType `AppsMFCC` header (`b"AppsMFCC"`, version `1u16`, `size_total`, `size_chunk`, `"Design Science, Inc.\0"`, followed by the raw MTEF 5.0 bytes).
  - Ensure all `.emf` previews generated during `.docx` conversion ([`src/docx/job.rs`](src/docx/job.rs)) and single-equation export automatically carry embedded MTEF 5.0 data so new MathType versions can open the equation directly from the `.emf`.
- [x] **Task 1.2: Extract MTEF Data from `.emf` Pictures (`extract_mtef_from_emf`)**
  - Implement `extract_mtef_from_emf(data: &[u8]) -> Option<Vec<u8>>` in [`src/ole.rs`](src/ole.rs) to parse `EMR_COMMENT` (`0x46`) records and reassemble `AppsMFCC` MTEF chunks (mirroring [`extract_mtef_from_wmf`](src/ole.rs)).
  - Update [`src/docx/to_omml.rs`](src/docx/to_omml.rs) (`try_convert_wmf_run` ➔ `try_convert_metafile_run`) so standalone `.emf` equations (where OLE `.bin` was stripped) are also detected and converted seamlessly.
- [x] **Task 1.3: Legacy MathType ➔ Modern MathType Upgrader Pipeline**
  - Implement `upgrade_legacy_mathtype_docx` in [`src/docx/`](src/docx/mod.rs):
    - Scans `.docx` for legacy `Equation.3` / `Equation.2` OLE objects, MTEF 3.0 streams, standalone `.wmf` equations, or old MathType OLE objects with blurry WMF previews.
    - Decodes them to `MathNode` (MathML) and re-encodes to either:
      1. **Modern OMML (`<m:oMath>`)** (for modern MathType Web Add-in & native Word editing), or
      2. **Modern MathType 7 (`Equation.DSMT4` MTEF 5.0 + Vector `.emf` with `EMR_COMMENT` MTEF)**.
- [ ] **Task 1.4: Single-Equation Flat OPC (`pkg:package`) Packager & Parser**
  - Create `src/docx/flat_opc.rs`:
    - **Packager (`mathml_to_flat_opc`):** Takes a `MathNode` and target mode (`ModernOmml` or `ModernMathtypeOleEmf`), and returns a complete `<pkg:package>` XML string containing `/word/document.xml`, `/word/_rels/document.xml.rels`, `/word/embeddings/oleObject1.bin` (base64), and `/word/media/equation1.emf` (base64 with embedded MTEF).
    - **Extractor (`flat_opc_to_mathml`):** Takes the OOXML string returned by Word's `getSelection().getOoxml()` or WPS's selection XML, locates `<m:oMath>`, `oleObject*.bin`, `.emf`, or `.wmf` inside the `<pkg:part>` entries, and decodes it to MathML.

### Phase 2: Local Communication Bridge Server
**Goal:** Expose the Rust engine over a local loopback server that Office/WPS Add-ins and the Tauri UI can communicate with reliably.

- [ ] **Task 2.1: Local HTTP/WebSocket Bridge (`127.0.0.1:17890`)**
  - Embed a lightweight server (`axum` or `tiny_http`) inside the Rust application.
  - Include CORS headers AND `Access-Control-Allow-Private-Network: true` to satisfy modern Chromium/WebView2 Private Network Access rules when called from HTTPS Office Add-in origins.
  - Support Custom URI Scheme (`matheditor://open?...`) as a fallback trigger on macOS/Windows if the desktop agent is not yet running.
  - Endpoints:
    - `GET /health`: Returns version and status.
    - `POST /session/open`: Receives Flat OPC XML / MathML / LaTeX from Word/WPS, decodes to MathML, focuses the Tauri editor window, and holds a session ID.
    - `GET /session/:id/wait`: Long-poll / WebSocket endpoint that resolves with the updated Flat OPC XML or OMML when the user clicks **Insert / Update** in the editor.
    - `POST /convert/snippet`: Instant stateless conversion (e.g., for **Toggle LaTeX** or single-equation **Legacy ➔ Modern** conversion in Word/WPS).
    - `POST /convert/document`: Batch convert `.docx` files on disk (OMML ⇄ Modern MathType OLE+EMF, or Legacy MathType ➔ Modern MathType).

### Phase 4: Microsoft Word Add-in (Modern Add-in Architecture)
**Goal:** Provide a Ribbon Tab and Taskpane/Command workflow in Microsoft Word modeled after the modern MathType Add-in.

- [ ] **Task 4.1: Office Add-in Manifest & Ribbon Design (`manifest.xml`)**
  - Custom Ribbon Tab `Math Editor` with buttons:
    - **Insert Equation:** Opens editor to insert a new equation at cursor.
    - **Edit Equation:** Reads selected equation (OMML, Legacy MathType OLE/WMF, or Modern EMF) and opens it in the editor.
    - **Toggle LaTeX:** Converts selected `$...$` or `\[...\]` text in Word into an equation (or vice versa).
    - **Upgrade Legacy Equations:** Converts selected equation(s) or iterates through inline shapes/equations in the active document to upgrade Legacy MathType (`Equation.3` / `.wmf` / old OLE) ➔ Modern MathType (OMML or DSMT4 + EMF-MTEF).
    - **Batch Converter (Desktop):** Opens the Tauri Batch Converter window for fast full-file `.docx` processing.
- [ ] **Task 4.2: Insert & Edit Implementation (`Office.js`)**
  - **Insert / Replace:** Use `Office.context.document.setSelectedDataAsync(flatOpcXml, { coercionType: Office.CoercionType.Ooxml })`.
  - **Edit Selection:** Call `Word.run(async (context) => { const ooxml = context.document.getSelection().getOoxml(); ... })`, send `ooxml.value` to `POST /session/open` on the local bridge, and replace selection with the returned Flat OPC payload on save.
- [ ] **Task 4.3: In-Document "Legacy MathType ➔ Modern MathType" Action**
  - Traverse document paragraphs/inline objects in chunks via `Office.js` (for small/medium documents) or prompt to run via the instant Rust file converter (for large 100+ equation documents).
  - Each legacy OLE/WMF snippet is sent to `POST /convert/snippet` and replaced in-place with Modern OMML or Modern MathType OLE + EMF-MTEF.
