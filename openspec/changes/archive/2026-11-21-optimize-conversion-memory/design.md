# Design

## Context

See [proposal.md](./proposal.md) for motivation. Current codebase constraints verified during exploration:
- `src/docx/pipeline.rs`, `src/docx/to_omml.rs`, and `src/docx/upgrade.rs` convert disk files by reading the entire `.docx` into `Vec<u8>` (`std::fs::read`), decompressing all entries into `Package::entries` (`src/docx/package.rs`), parsing full `Element` DOM trees (`src/xml.rs`), cloning every equation subtree into `Vec<*WorkItem>`, collecting every parallel result into `Vec<Result<*Prepared>>`, and finally holding `Package::entries` + parallel ZIP `chunks` + serialized output `Vec<u8>` simultaneously before `std::fs::write`.
- `src/xml.rs` stores `prefix: Option<String>`, `local: String`, `ns: Option<String>`, `nsdecls: Vec<(Option<String>, String)>`, and `Attr` strings as separate heap allocations per node, amplifying DOM footprint and multi-thread allocator fragmentation (notably glibc `ptmalloc2` arenas on Linux across 16 `rayon` threads).
- `desktop/src/batch.rs` already uses sibling `tempfile` + `persist` / `persist_noclobber` for crash/cancellation safety, whereas `src/docx/` file entry points previously relied on reading all input bytes before writing `output_path` in place.
- `Cargo.toml` already includes `zip = "0.6"` (which supports `ZipArchive::new(BufReader<File>)` and `ZipWriter::raw_copy_file` / `raw_copy_file_rename`) and `rayon = "1"`. Note `desktop` does not depend on `tempfile` inside the root `eqntide` crate yet (check if `tempfile` is needed in root `Cargo.toml` or if a sibling temp-file guard helper using `std::fs` / `uuid` avoids adding a new dependency).

## Goals / Non-Goals

**Goals:**
- Reduce Peak RSS for single `.docx` documents with thousands of equations across Linux, macOS, and Windows using pure Rust changes.
- Eliminate simultaneous retention of `input` bytes, `output` bytes, full `WorkItem` + `Prepared` collections, and duplicate `Package::write` chunk buffers.
- Cut `xml::Element` heap allocations via static/interned OOXML namespace URIs and prefixes.
- Guarantee deterministic byte-level or entry-level equivalence with existing conversion outputs and preserve all security bounds (`MAX_DOCX_ENTRY_BYTES`, `MAX_DOCX_TOTAL_BYTES`).

**Non-Goals:**
- Event-based streaming XML parser/rewriter for `word/document.xml` (Phase 2; excluded here to avoid subtle namespace/table/`sanitize_document_baselines` regressions).
- Platform-specific global allocators (`jemalloc` / `mimalloc`), since `desktop/src/main.rs` enforces `#![forbid(unsafe_code)]` and root-cause data-retention fixes apply uniformly on Windows, macOS, and Linux.
- Multi-file concurrent `.docx` processing (sequential file-by-file + multi-core per-file remains the bounded-memory design).

## Decisions

### 1. Bounded-Chunk Equation Parallelism (`CHUNK_SIZE = 128`)
- **Decision**: Split `paths` / work references inside `Job::convert_part_equations` (`EQUATION_CHUNK_SIZE = 128` in `src/docx/job.rs`), `rewrite_part_parallel` (`TO_OMML_CHUNK_SIZE = 128` in `src/docx/to_omml.rs`), and `upgrade_content_part` (`UPGRADE_CHUNK_SIZE = 128` in `src/docx/upgrade.rs`) into slices of `128` items. Run `par_iter()` per chunk, assemble/apply outcomes immediately, release the chunk's work references, transient media cache, and `Prepared` vectors, and repeat. Also delegate `UpgradeTarget::ModernOmml` on disk in `upgrade_legacy_mathtype_docx_with_cancel` directly to `convert_to_omml_with_cancel` so both upgrade targets share streaming I/O and chunked execution.
- **Rationale**: `128` equations easily saturates 8–32 CPU cores via `rayon` work-stealing while capping transient `ole_bin` + `emf`/`png` + prepared XML memory at ~1/20–1/40 of a 3,000–5,000 equation document. In `job.rs` (`OMML -> MathType`), `EquationWorkItem<'a>` borrows `&'a Element` directly from `self.doc_root` per chunk (avoiding cloning every `<m:oMath>` subtree unless `EmbedMode::OmmlFallback` needs a fallback clone). In `to_omml.rs` and `upgrade.rs`, `ToOmmlWorkRef` / `UpgradeWorkRef` store only element paths and work kinds, resolving `&Element` and loading chunk-scoped `.bin`/`.emf`/`.wmf` entries transiently via `Package::load_transient_batch` + `PartLookup` before dropping `chunk_cache` at the end of each chunk. Because multi-object `<w:r>` runs in `to_omml.rs` can splice multiple `<m:oMath>` siblings back into a parent, `rewrite_part_parallel` tracks `extra_children` shifts across chunks so later chunk paths remain exact.
- **Alternative considered**: Parallelizing across chunks with a streaming channel (`mpsc`) to overlap compute and assembly. Rejected for Phase 1 because bounded synchronous chunk loops are simpler, lock-free, preserve exact `eq_num` order deterministically, and keep cancellation checks immediate between chunks.

### 2. File-Backed Lazy ZIP Reader + Streaming ZIP Writer with Sibling Temp File
- **Decision**: Refactor `src/docx/package.rs` around `EntryData::{Loaded(Vec<u8>), Deferred { archive_index }, Removed}` to separate metadata/modified-entries from untouched entries backed by a `ZipArchive<BufReader<File>>` (while preserving `Package::read(&[u8])` / `convert_bytes*` for in-memory callers and existing unit tests):
  - **Lazy read**: `Package::open(path)` scans only central-directory metadata (`name`, `is_dir`, `modified`, declared `size`), enforces `MAX_DOCX_ENTRY_BYTES` and cumulative `MAX_DOCX_TOTAL_BYTES`, and leaves entries `Deferred` (without caching them in `Package::entries` on read). `Package::get()` serves only `Loaded` entries; XML parts are parsed transiently via `Package::load_xml()` (dropping raw decompressed bytes immediately after parsing), and per-chunk equation media are loaded transiently into a caller-owned `HashMap` via `Package::load_transient_batch()` and queried lock-free through `PartLookup`. `read_deferred` re-verifies that actual decompressed length matches the central-directory size and stays within `MAX_DOCX_ENTRY_BYTES`.
  - **Pass-through & streamed write**: `Package::write_to_file_atomic(output_path, cancel)` writes directly to a `ZipWriter<BufWriter<File>>` backed by a sibling `.eqntide-tmp-<uuid>.docx` file (created with `0o600` on Unix and a `TempFileGuard` RAII drop-guard that deletes the temp file on error/cancellation). It follows output symlinks (up to 40 hops), verifies writeability and preserves existing file permissions, copies untouched `Deferred` entries via `raw_copy_file` without decompression or recompression, and flushes modified/new `Loaded` entries in bounded parallel batches (`STREAM_COMPRESS_BATCH = 64`) before `sync_all()`, closing `self.source = None`, and calling `std::fs::rename`.
  - **Early release of consumed parts**: In `to_omml.rs` and `upgrade.rs`, deferred `.bin`/`.emf`/`.wmf` entries are only ever held in the per-chunk `chunk_cache` (dropped before the next chunk), and `cleanup_unreferenced_files` propagates XML parse errors from `.rels` via `load_xml` and marks unreferenced parts as `EntryData::Removed` so `write_to_file_atomic` skips copying them (and `pkg.remove` drops `Loaded` bytes in in-memory mode).
- **Rationale**: Eliminates the largest multi-buffer overlap (`input: Vec<u8>` + full `Package` + `chunks` + `output: Vec<u8>`). Sibling temp-file + atomic rename keeps `input == output` in-place calls (CLI/bridge) and cancellation 100% safe without needing `tempfile` as a new root dependency (a small RAII `TempFileGuard` in `src/docx/package.rs` using `uuid::Uuid::new_v4()`, already in `Cargo.toml`, works cross-platform).
- **Alternative considered**: Keeping `std::fs::read` + `std::fs::write` and only chunking `Package::write`. Rejected because `input` + `Package.entries` + `output` would still hold 3x the document size in RAM and force full decompression/recompression of large embedded images.

### 3. Interned OOXML Namespaces & Prefixes (`Cow<'static, str>`) in `src/xml.rs`
- **Decision**: Change `Element::prefix`, `Element::ns`, `Element::nsdecls`, `Attr::prefix`, `Attr::ns`, and `NsDecl` in `src/xml.rs` from `String` to `Cow<'static, str>` (plus `pub(crate) fn intern_ns(&str) -> Cow<'static, str>` and `intern_prefix(&str) -> Cow<'static, str>` matching standard OOXML/MathML/VML/OLE/Relationships/ContentTypes URIs and common prefixes `"w"`, `"m"`, `"r"`, `"v"`, `"o"`, `"mc"`, `"a"`, `"pic"`, `"wp"`, `"w14"`, `"w15"`, `"w16"`, `"wps"`, `"wpc"`, `"pkg"`, `"mtype"`, `"xml"`). Keep `Element::new(ns: Option<&str>, prefix: Option<&str>, local: &str)` and `set_attr` signatures accepting `&str` so external callers require minimal or zero signature changes.
- **Rationale**: In a document with 100,000+ XML elements, almost every `ns` string is one of ~16 fixed URIs and almost every `prefix` is 1–5 chars. `Cow::Borrowed(&'static str)` performs zero heap allocation, zero `memcpy`, and zero `free` across threads, cutting both DOM RAM and glibc/heap fragmentation.
- **Alternative considered**: Full string-interner arena (`lasso`/`string-interner`) with handle IDs. Rejected because it changes `Element` equality/ergonomics (`el.local == "oMath"`, `el.ns.as_deref()`) across the entire crate and tests.

### 4. Early DOM & Buffer Lifetime Scoping
- **Decision**: In `src/docx/pipeline.rs`, drop `job.doc_root` and `job.rels_root` immediately after `xml::to_bytes` by resetting them to lightweight empty `Element::new(None, None, "root")` placeholders before loading the next XML part; in `src/docx/to_omml.rs` and `src/docx/upgrade.rs`, scope `doc_root` and `rels_opt`/`rels_root` locally inside `convert_content_part` / `upgrade_content_part` so each part's DOM drops before the next part loads.
- **Rationale**: Prevents holding `word/document.xml`'s full DOM while parsing subsequent parts (`header*.xml`, `footnotes.xml`, etc.).

## Risks / Trade-offs

- **Windows atomic replace on `input == output`** -> On Windows, `std::fs::rename(temp, dest)` fails if `dest` is still open, so we MUST drop/close the source `ZipArchive<BufReader<File>>` handle *before* renaming `temp` over `destination`. Mitigation: explicitly set `self.source = None` after `file.sync_all()` and before `std::fs::rename`.
- **Symlinked or read-only output destinations** -> `std::fs::rename` would replace a symlink itself rather than its target, or bypass an existing target file's permissions. Mitigation: `write_to_file_atomic` resolves symlink chains (up to 40 hops), opens existing target files with `write(true)` to respect permissions before creating the temp file, and applies original permissions to the temp file before renaming.
- **Duplicate ZIP entry names in malformed `.docx`** -> Existing `Package::read` keeps the last entry when duplicate names exist. Mitigation: `Package::open` overwrites the existing entry slot in `self.index` when scanning the central directory so lazy reads and `raw_copy_file` preserve exact last-entry-wins semantics.
- **Multi-object `<w:r>` path shifts across chunk boundaries (`to_omml.rs`)** -> Replacing one `<w:r>` containing multiple MathType OLE objects with multiple `<m:oMath>` siblings shifts child indices of subsequent items under the same parent across later chunks. Mitigation: `extra_children` records cumulative sibling insertions per parent path between chunks, covered by `multi_object_run_at_chunk_boundary_keeps_later_sibling_paths`.
- **Unreadable `.rels` during orphan cleanup (`to_omml.rs` / `upgrade.rs`)** -> Silently ignoring `.rels` parse failures during `cleanup_unreferenced_files` could misclassify referenced assets as unreferenced. Mitigation: `cleanup_unreferenced_files` propagates `load_xml` errors so in-place conversions abort cleanly before committing (`unreadable_relationships_abort_in_place_cleanup`).
- **`xml::Element` public field type (`Cow<'static, str>` vs `String`)** -> Any code pattern-matching or constructing `Element` struct literals with `String` fields would need updating. Mitigation: audit all `Element` / `Attr` struct literals and `.ns`/`.prefix` accesses via compiler errors across workspace crates (`eqntide`, `eqntide-editor`, `desktop`, `tests/`) during implementation; `Element::new`, `attr()`, `is()`, `set_attr()` keep `&str` signatures.
- **Chunk size vs. single huge equation** -> `CHUNK_SIZE = 128` bounds multi-equation documents; if one single equation itself has an extreme PNG canvas, `MAX_PIXELS` (`6_000_000`) still bounds per-equation raster memory. Mitigation: keep existing `MAX_PIXELS` / `MAX_WIDTH_PX` guards intact.
